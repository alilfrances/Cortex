- Upgrading from 0.9.x rebuilds the index automatically, in full, once. The repository's row now records a graph format version (`repos.graph_version`, added by an automatic migration; `GRAPH_FORMAT_VERSION = 1` in `src/cortex/store.py`). An index stamped with an older version, including every pre-0.10.0 database, is rebuilt in full by the next `cortex ingest --update`, `cortex_refresh`, or MCP auto-refresh (the summary and `auto_refreshed` carry `full_reindex_reason`), and that repository's query cache is cleared. The MCP freshness check and the SessionStart hook report such an index stale even when no file changed (the hook adds "built by an older Cortex"). The OSS section of `evals/RESULTS.md` now names the parser backends used and flags a regex-fallback run as not comparable. Before this, an incremental refresh only re-extracted changed files, so untouched files kept call edges without the call-site contract, and C/C++/JS/TS/Go/Rust/Swift/Java/Ruby files kept no call edges at all, until someone ran a full `cortex ingest` by hand. The earlier bullets' "until re-indexed in full" caveats no longer apply. - Fix four call-extraction defects found on real upstream code while vendoring the OSS eval snapshots (`tests/test_calls_oss_regressions.py`, each test fails without its fix): (1) C++ `if (x) Q_EMIT sig();` in an unbraced control-flow body (tree-sitter parses `Q_EMIT` as an `ERROR` node) also produced a `calls` edge to the signal; it is now only the `emits` edge (oKcerG/SortFilterProxyModel `Filter::invalidate`). (2) Go method-receiver names were kept in an `id(frame)`-keyed table; CPython reuses ids of collected frames, so `r.Context()` in a plain `func Vars(r *http.Request)` could be classified as an implicit-`this` call (gorilla/mux); the receiver name now lives on the frame. - Resolve Python `calls` edges to real symbols with one deterministic, indexed repo-wide pass (`src/cortex/callresolve.py`, run by `build_graph` and by the incremental merged-store pass), so dead-code, `cortex_path`, `cortex_references`, `cortex_relations` and risk fan-in finally see cross-module callers (they used to end at an unmatchable `name:<callee>` endpoint). Every call edge now carries the call-site contract in its metadata (`callee`, `receiver`, `receiver_kind` of `none`/`this`/`self`/`scoped`/`var`/`new`/`chain`, `scope`, `receiver_type`, `enclosing_class`, plus `scope_module`/`import_module`/`alias`/`super` for Python), module-level and class-body calls are now recorded (source `file:<path>` or the class symbol), and edge ids are `ast:<path>:calls:<owner>:<receiver.>callee:<lineno>`. Resolution tiers, first hit wins: `scoped` (`Cls::m`, `pkg.m`, module aliases), `this` (`self`/implicit this), `declared_type` (annotated/constructed receiver types), `inherited` (bounded BFS over `inherits`, depth 6, cycle-safe), `same_file`, `import_scoped` (one hop, plus package `__init__` re-exports), `repo_unique`; a resolved edge gets `metadata.resolution`. More than one candidate at the deciding tier keeps `name:<callee>` and sets `confidence: LOW`, `ambiguous: true` and sorted `candidates` (at most 8). Untyped receivers, methods, builtins and external modules are never guessed from a unique label. The incremental pass resolves every edge from its metadata (never from its previous target) and re-resolves only edges in the batch's files, edges whose callee label was added or removed by the batch, edges whose resolved target vanished, and typed/member edges when classes or inheritance changed in the batch, so removed or newly ambiguous targets are reset (confidence restored) and previously unresolved edges in untouched files resolve; it converges to what a full ingest writes (`tests/test_call_resolution.py`). All indexes are hash maps built once per pass (O(nodes + edges); a 2,000-symbol graph resolves in ~70 ms, and `evals/perf_ingest.py` still reads one file in ~0.28 s). A database indexed before 0.10.0 is rebuilt in full once on its next refresh (see the graph-format bullet above). - Make git history rename-aware. Commits are now read with rename detection, and each commit records its renames (stored in a new `commits.renames_json` column added by an automatic migration). A path reused by an unrelated file later does not inherit the old file's history. - Extract JavaScript, TypeScript and TSX `calls` edges (tree-sitter) and resolve them. Sites: free calls, `new T(...)` (kind `new`), `this.m()`/`super.m()`, `obj.m()`, `obj?.m()`, `this.field.m()`, `new T().m()`, `(x as T).m()`, chains (`a.b.c()` -> receiver `a.b`, kind `chain`, unresolved), with `await`/parentheses/`!` unwrapped. Receiver types: TS parameters, `const x: T`, class fields, constructor parameter properties (`constructor(private svc: Svc)`), and `new T()` inference (the only inference for JS). Imports are modelled by the extractor itself because the generic `imports` edges of JS files still target `module:<spec>` (frozen): relative specifiers are probed for extensions, `index.*` and `.js`->`.ts`, and the call edge carries `import_spec`/`import_file` (named, default and aliased bindings, with the callee being the exported name; `require` aliases and destructuring too), `scope_file`/`scope_namespace` (`ns.f()` for `import * as ns`/`require`, class statics for named/default class imports) and `receiver_type_file` (an imported type name picks the imported class when two classes share a name). Resolver rules: an explicit import binding resolves only inside the file it names (beating same-file and repo-wide guesses) and an external package stays `name:<callee>` with unchanged confidence (a repo function named `useState` is never guessed); JS/TS bare `foo()` is never implicit-this (`implicit_receiver: false`). ## 0.7.2 — 2026-07-08

- Fix `cortex_search_symbols` (P0) burying the queried symbol under alphabetical, unrelated results. `CortexStore.search_nodes` matched query tokens against each node's `source_ref` (file path) with the same weight as the symbol name, so a query like `CortexStore` matched the *path* of every symbol under `src/cortex/` and ranked `__init__`, `_bfs_proximity`, … equal to the real class (then sorted alphabetically). With no `ORDER BY`, the genuine node could also be dropped by the candidate `LIMIT` before ranking ran. Now the SQL fetches label matches first (`ORDER BY` a label/signature/path priority) so a name match is never truncated away, and the Python ranker buckets strictly name → signature → path, so path-only hits always rank last. (Not related to `enrichment_enabled`, which does not gate symbol matching.)
- Fix `cortex_read_symbol` (P1) returning a single declaration line for C/C++/QML/JS/… symbols. The regex structural backend hard-coded `span_end = span_start`; it now brace-matches the body (skipping strings and comments) to the closing brace, and anchors the line number and signature on the symbol *name* so leading `^\s*` / greedy return-type matches no longer skew the span onto a blank or preceding line. Also fixes `_signature` overshooting toward EOF for a symbol on the final line with no trailing newline.
- Fix `cortex_impact` (P2) listing commit SHAs as impacted paths ranked `1.0`. Commit nodes default to `granularity="file"` and link to files via COCHANGE `touches` edges, so `rank_file_impact` counted them as file neighbors; it now excludes commit nodes with the same guard the community/rank layers use.
- Improve `cortex_query` relevance (P2) when the task names a language or extension: same-language files are boosted and other code languages demoted (multiplicatively, so unrelated files are never seeded by language alone), so e.g. a QML task no longer resolves to the same-named C++ file.
