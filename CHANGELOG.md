# Changelog

## Unreleased

Part 1 of the 0.12.2 field-report fixes (third pass on `cortex_risk` map loss and `cortex_query` misses). No graph format change yet.

- `scripts/perf/synthetic_repo.py --field-shape`: a profile with the shape of the reviewer's C++/Qt repository, so fixes are accepted on it and not only on hand-built fixtures. It adds a base class with six same-named class definitions (real header, three mocks under `tests/`, a nested class, a JS helper), derived classes (some through an intermediate base) that override its virtuals, `inherits` written as the extractor emits them (`name:` for in-repo bases, `module:` for QML roots; 0 `symbol:`), a central manager `.cpp` whose out-calls are mostly accessors reached through a `Base*` or a `qobject_cast<T*>` local (about 80% unresolved), a second manager called from its event handler, concatenated lowercase file stems (`widgetwaitready.cpp` declares `WidgetWaitReadyStep`; about 55% of files), a history where every 7th commit touches `CMakeLists.txt`, and tests for one derived class in four (about 83% of the files changed over 100 commits have no reaching test). Output of every other profile is byte-identical; the stable names are in `FIELD_SHAPE` and the module docstring. Not matched: repository-wide, `calls` resolve about 90% of the time (the default generator's modules all resolve; field: 26%), only the manager's do not. `tests/test_synthetic_field_shape.py` pins the profile.
- `cortex_risk` no longer loses the per-file test map to `uncovered_changed_files`. In 0.12.1 that list was not part of the truncation at all; on a range where most changed files have no test it alone exceeded the budget, so every other step ran to the end and the map and `tests_to_run` were emptied (`budget_feasible: false`). Now `uncovered_changed_files` is ordered by the changed file's risk rank (the `files` order), then path, so a prefix is the riskiest subset; **this reorders the list compared with 0.12.1 (it was alphabetical)**, and the `cortex_risk` payload goldens changed only by that reorder. When the result is over budget the list is first cut to `UNCOVERED_FLOOR = 20` entries and `uncovered_changed_files_total` records the full count (the key appears only when the list was shortened, so results that fit are unchanged apart from the order); it goes below 20, down to none, only after `tests_to_run` has reached its floor of 10 and before the map is cut. If a result is still over budget after every step (a collection key the truncator does not know about), a minimal payload is returned instead of an emptied one: `status`, `range`, `tests_run_all` and its reason, the counts, and as much of the lists and the map as fits, with `minimal_payload: true` and every other key named in `omitted_fields`. It is only used when it fits; at absurd budgets (for example 0) nothing fits and `budget_feasible` stays `false`. Invariant test `test_every_collection_key_is_reducible` (inflates every list/dict key of a real `analyze_risk` result 50x on a `--field-shape` repo) fails when a new collection key is in neither `_RISK_REDUCIBLE_KEYS` nor `_RISK_SCALAR_KEYS`. Measured on `--field-shape --modules 200 --commits 120` (`HEAD~100..HEAD`: 460 changed files, 387 uncovered, 72 with a test map, 99 impacted tests): 0.12.1 at budget 2000 is infeasible with an empty map and no tests (the reviewer's failure, reproduced); now `budget_feasible: true`, map for 30 of 72 changed files (`tests_by_changed_file_omitted: 42`), 10 tests, `uncovered_changed_files_total: 387`; at 4000 the map for 72 of 72 and 39 of 99 tests; kept map entries decode identically to the budget-100000 run and are the top-k changed files by risk. At `--modules 40` (254 changed files) the map is complete at 2000. **Not yet verified on the reviewer's repository**: the acceptance there (map for at least 34 of 37 files at 2000, all 42 tests at 4000, `uncovered_changed_files_total == 276`) needs their pinned range; on the synthetic profile the 4000-budget run keeps 39 of 99 tests, not all of them.
- `cortex_refresh` reports `mode: "full"` when an incremental refresh of an older-format index was rebuilt in full (it said `incremental` next to a `full_reindex_reason` that said "rebuilt in full").

## 0.12.1 — 2026-10-21

Fixes for a test review of 0.12.0 on a large C++/QML repository (verdict, evidence and task list: `docs/plan-0.12.1-review.md`). No graph format change.

- `cortex_risk` keeps `tests_by_changed_file` on large diffs. The 0.12.0 entry below said the map is "given up last"; it was not. The map was decided (re-encoded or dropped) before `directives` and `tests_to_run` were shortened, and on a big diff `tests_to_run` alone is larger than the whole budget, so the map was always dropped (`HEAD~30..HEAD` on the 2.2k-file bench repo, 117 changed files and 185 tests, default budget 2000). The new order when over budget: shorten `files`; re-encode the map (lossless) against its own test table; drop the other secondary buckets; drop the `reason` text of `tests_to_run` entries (named as `tests_to_run.reason` in `omitted_fields`); shorten `directives`; shorten `tests_to_run` down to 10 entries (`TESTS_TO_RUN_FLOOR`); shorten the map to the highest-risk changed files (`tests_by_changed_file_omitted` counts the rest); only then cut `tests_to_run` below the floor, with the map fitted first and the tests given the room left over, and drop the map whole only if not one changed file fits. Result on that range: at budget 2000 the map is kept for 12 of the 117 changed files (the long paths alone are about 1.4k tokens in index form), at 4000 for all of them. **Breaking for parsers of the 0.12.0 shape:** the index encoding `tests_to_run_index` (indices into `tests_to_run`) is replaced by `tests_by_changed_file_encoding: "test_table"` with its own `tests_by_changed_file_tests` list, so cutting `tests_to_run` can no longer invalidate the map. `returned_count` now counts toward the fit, so a fitted payload no longer ends one token over its limit. Regression tests: `tests/test_risk_truncate.py` (`_large_diff_result`).
- `cortex_query` ranks the callees of its top matches above files that only share a word (0.12.0 review). The top match's resolved callee, a base-class implementation, never appeared: call expansion was file-level and undirected (every neighbour of the 8 best files, callers included, got the same lift of at most 20), 20 is below any file whose name or path shares one task word (40-100+), the 0.12 reserve only held budget back from a file's third and later spans, and only one hop was followed. Now the callees of the 6 best-scoring symbols are scored from the calling symbol's own score (`CALLEE_HOP_SHARE`: 0.9 for a call into another file, 0.8 for a second one; calls inside a file are walked through without spending a hop, and each function is reached by its shortest route (0-1 BFS); at most 4 other-file callees per function in call-site order) and so are the bases of the seed's class (0.6); callers are not expanded. Each callee gets its own span candidate and its file is lifted to a quarter of that score, and the item says why: `why: {type: "call", from, to, hop}`, compact form `calls: <seed> -> <callee>`. The 0.12.0 reserve (`CALL_EXPANSION_BUDGET_SHARE`, `SPANS_BEFORE_RESERVE`) is removed: callees now compete on score and the reserve did not protect them. The call index (one pass over all edges) is memoised with the graph cache; interleaved cold-query timing on the 2.2k-file bench repo is unchanged within noise. Eval gate: recall and file_recall unchanged on all 68 historical rows; precision +0.17 on two rows (the 0.12.0 reserve had cost it) and -0.25 on two (one extra callee); `precision_at_3` +0.33 on one. New `COMPANION_GOLD_TASKS` eval (`companion_repo`, a C++/QML fixture with 35 term-only distractor files): fails on 0.12.0 at budgets 600 and 900, passes now; `SPREAD_GOLD_TASKS` still passes. Goldens regenerated: `evals/default_matrix.json` (those rows), `evals/default_files.{regex,treesitter}.json`.

Upgrading: the graph format is 5; an older index is rebuilt in full by its next refresh (the MCP tools report it stale until then).

**Graph format 5 (full rebuild on first refresh).**

- Qt headers no longer produce a fabricated `QObject` class. The regex Qt passes found a class's owner with a pattern that needed `{` on the `class` line; with Qt's usual brace-on-next-line style no owner was found and `Q_PROPERTY`/`Q_INVOKABLE` members were attached to a made-up `symbol:<file>:QObject` class (17 headers / 64 nodes in the vendored Qt fixture). Owners now come from the extracted class spans, with a brace-scan fallback that handles a brace on a later line and export macros (`class MYLIB_EXPORT Foo`); a member outside any class is skipped. Brace-on-next-line classes now also get their `qt: qobject` tag and, in the regex backend, their `inherits` edges. No checked-in golden changed (the fixtures use same-line braces); `tests/test_qt_owner_extraction.py` covers both backends and the vendored project.
- Tree-sitter C++ parses Qt headers cleanly. `Q_OBJECT`, `Q_PROPERTY(...)`, `Q_CLASSINFO(...)`, `Q_ENUM(...)`, `Q_INVOKABLE`, `signals:`/`slots:` labels and all-caps export macros (`class MYLIB_EXPORT Foo`) made the grammar error-recover; with an export macro the whole class was read as a function named after its base (`QObject`) and the real class disappeared. The macros are now blanked (length-preserving, on bytes) in the copy that is parsed; signatures and call extraction still read the original text. No checked-in golden changed.

- `cortex_query` ranks files on a file-level graph. Personalized PageRank ran over every symbol node and edge (4.3s of a 7.5s cold query on the 2.2k-file bench repo) to add a bonus of at most 0.07 for files with no keyword hit. It now runs on `rank.collapse_to_file_graph` (symbols folded into their file, self-loops dropped, parallel edges merged): 0.28s, memoised with the graph cache. Under a deadline the rank step gets whatever remains after reserving 25% of the budget (at least 2s); if that runs out the query returns its keyword results with `degraded: ["graph_rank"]` and a note instead of `deadline_exceeded`, and a degraded result is not cached. Skeleton body choice now uses the span match scores instead of symbol PageRank. Eval gate (`scripts/perf/eval_compare.py`): no row's recall or file_recall decreases, means unchanged except precision 0.4484 -> 0.4498; one row improves (`python_app` "markdown setup" `skeleton_off` precision 0.4 -> 0.5) and the filler order of 11 rows changes. Goldens regenerated: `evals/default_matrix.json` (that one row) and `evals/default_files.{regex,treesitter}.json` (selected file order/filler). `tests/test_bundle_locale_empty.py` no longer asserts the catalogue is *listed after* the implementation: in its 3-file repo that held only through a graph-bonus artifact (with a dozen unrelated files added the catalogue outranks the implementation both before and after this change); it now asserts the locale demotion on the keyword score.
- `cortex_search_symbols` results are cached per index fingerprint and arguments like `cortex_impact` (previously `_meta.cached` was always false); a hit still prices the ledger from the cached concise payload plus `why`, so `saved_tokens` is identical. `cortex_status` now reports `version`, and the MCP `serverInfo.version` comes from `cortex.__version__` instead of a second hard-coded literal. Golden changed: `mcp/shapes/cortex_status.{concise,detailed}.json` (new `version` key).
- Dead code: CMake/qmake build targets (`target:` nodes) are no longer candidates. They are entry points, have only outgoing `builds` edges, and every target in a `CMakeLists.txt` was reported. `_OverrideIndex._declares_method` looks methods up by name instead of scanning every method of every file (`analyze_dead_code` 8.2s -> 6.1s on the 2.2k-file bench repo; results identical, checked against the old scan). Goldens changed: `mcp/payloads/{regex,treesitter}/cortex_dead_code.{concise,detailed}.json` (the `qt_app` target finding disappears).
- A stopped dead-code analysis is kept and continued (report 0.11 #7). On a repository too big for one budget, `cortex_overview` was permanently `dead_code_partial`: the partial analysis was never cached, so every call redid communities, hotspots and the first candidates and ran out of time again. `analyze_dead_code` now returns a `cursor` and `progress` when stopped and accepts `resume`; resuming to the end gives exactly the findings of one uninterrupted run. The overview caches its partial analysis (cache version 2) and each call continues from the cursor without recomputing communities, hotspots, god nodes or surprising connections; the partial overview reports `dead_code_progress: {processed, total}`. A repo-wide `cortex_dead_code` call continues the overview's stopped scan, or its own cached stopped run; scoped calls are unchanged. On the 2.2k-file bench repo with `CORTEX_TOOL_TIMEOUT_SECONDS=4` the overview now completes in 4 calls of at most 4.3s each (before: never, about 11s of work repeated on every call).
- Dead-code analysis can stop while it builds its reference corpus. Reading every git-listed file and tokenizing them for the first candidate had no stop check, so a call could overrun its budget before reporting anything. `ReferenceCorpus` now polls the stop predicate every 200 files (`AnalysisStopped`); the candidate being processed is left unreported and the result is `partial`. A `path=`-scoped run also indexes only its own candidates' names instead of every symbol in the repository (results unchanged).
- `cortex_query` spreads its budget across files (report 0.11 #6). Every span of a name-matching file scores +100, so two files' methods could fill the whole bundle and the files they call into (score <= 20) never fit. (1) A symbol span lying inside an already selected span of the same file is skipped (it printed the same lines twice). (2) 15% of the budget is held back from symbol spans once a file already has two selected (`SPANS_BEFORE_RESERVE`), so a lone good hit is never squeezed; (3) the call-expanded files (callees, callers and bases of the best matches) then get that reserve, packed as a skeleton of only the symbols actually called (else the whole-file skeleton), and unused reserve is released to the normal pass. New `SPREAD_GOLD_TASKS` eval: recall 0.5 -> 1.0 in all four modes (kept out of `GOLD_TASKS`; `tests/test_bundle_spans.py` runs it). Eval gate (`scripts/perf/eval_compare.py`): recall and file_recall unchanged on all 17 historical tasks; two rows ("expired sessions are pruned", `skeleton_on`/`skeleton_off`) gain one call-expanded callee, precision 0.667 -> 0.5. A per-file score decay (planned) was not shipped: it moved no metric. Goldens regenerated: `evals/default_matrix.json` (those two rows), `evals/default_files.{regex,treesitter}.json`.
- `cortex_query` hot paths (results identical; verified on the bench repo for four tasks, and by `tests/test_bundle_why_index.py`). Each source is tokenized once and shared by term weighting, the symbol-span scoring and the semantic gate; symbol spans are not even cut for a file that shares no term with the task unless a symbol's own name matches (a span can only score through a term it contains). The "why" explanation of the selected items used one pass over every edge per item (O(items x edges), about 12M iterations at 620k edges); it now uses one indexed pass.
- `cortex_risk` truncation. A response over its budget now lists every key it removed in `omitted_fields` (it used to say only `truncated: true`). `tests_by_changed_file` is given up last among the secondary buckets (it used to go first) and, before being dropped, is re-encoded as indices into `tests_to_run` (`tests_by_changed_file_encoding: "tests_to_run_index"`). `files`, `directives` and `tests_to_run` are cut with a binary search instead of one `pop()` and a full re-serialisation per item. `omitted_fields` counts toward the budget. For a very large diff nothing helps much: `HEAD~30..HEAD` on the bench repo is 46k tokens against the 2k default, and even the compact per-file map is about 1.9k tokens; there the response now says exactly what is missing.
- `cortex_risk` test selection for C/C++. `testpatterns` now knows C/C++ test naming (`tst_foo.cpp`, `test_foo.cpp`, `foo_test.cpp`, `FooTest.cpp`, and `footest.cpp` inside a test directory), so `foo.cpp` pairs with them. Pairing is stricter: a test that is only inside a test directory must mirror the source's directory (or sit in the test root), and generic stems (`main`, `utils`, `common`, `config`, ...) never pair on name alone, so `ui/main.cpp` no longer selects every `tests/**/main.cpp`. These rules apply to C/C++ tests only; other languages pair as before. Pairing is an indexed lookup instead of a scan of every path per changed file, in `impacted_tests` and in `risk`'s `missing_tests` directive. Unresolved `inherits name:X` edges are attached by label only when at most 3 repo classes carry that label (`LABEL_ATTACH_MAX`); a ubiquitous or made-up base such as `QObject` no longer selects every subclass's tests. No checked-in golden changed.
- In-process graph cache. `fetch_graph` (JSON-decodes every node and edge; 2.0s at 79k edges and linear in edges) ran on almost every tool call. The read-only tools (`cortex_query`, `cortex_impact`, `cortex_context`, `cortex_risk`, `cortex_path`, `cortex_dead_code`, `cortex_overview`) now share one cached result per index, keyed by database, repo, indexed fingerprint and `indexed_at`, so another process's ingest invalidates it; `cortex_refresh` clears it. Cost: one graph held in memory (about what a single `fetch_graph` result takes); `CORTEX_GRAPH_CACHE=0` turns it off. `cortex_status` reports `graph_cache: {nodes, edges}`. Repeat calls on the 2.2k-file bench repo: `cortex_impact` 3.8s -> 0.12s, `cortex_path` 4.05s -> 0.18s, `cortex_risk` 3.1s -> 1.5s. Golden changed: `mcp/shapes/cortex_status.{concise,detailed}.json` (new `graph_cache` key).
- Token-savings ledger no longer runs a tool a second time. `cortex_search_symbols`, `cortex_relations`, `cortex_path` and `cortex_overview` used to be re-dispatched in `detailed` format after the call, outside the deadline and the status registry (for `cortex_path` that was 2.85s of 6.3s on the 2.2k-file bench repo). The handlers now stash their detailed rendering and the ledger counts that; `saved_tokens` values are unchanged. The ledger also runs inside the status registry's timing, so `cortex_status.slowest_seconds` no longer under-reports.

Speed (results unchanged; goldens untouched by these):

- Full ingest was quadratic: every `#include`/import that did not match a path exactly scanned all known paths for a unique basename, and `build_file_layer` looked up each file's own node by scanning every node so far. Both are now indexed lookups (the produced graph is byte-identical).
- `cortex_risk` paired headers with implementations by scanning every path for every path (43s of a 51s call on a 6k-file repo); it now uses a stem index, and results are cached per diff.
- `cortex_query` cached identifier splitting, precomputed PageRank outgoing weights (bit-identical, asserted against the old loop) and stopped loading the graph and sources twice.
- Incremental refresh and detailed `cortex_overview` no longer load the whole graph just to count parser backends (`CortexStore.parser_backend_counts`); `cortex_dead_code` reuses the overview's cached analysis; the overview report-fit search is bounded; reference scans are lazy (stopping once the token budget is spent) and compile their access patterns once; community detection ignores `calls` edges again (two thirds of the graph since 0.10.0).

Behaviour:

- Time budget: `cortex_query`, `cortex_risk`, `cortex_impact`, `cortex_path` and standalone reference scans now honour `CORTEX_TOOL_TIMEOUT_SECONDS` and return `deadline_exceeded`; soft stops are counted (`total_soft_deadline`, per-tool `soft_deadline_count`); a read tool no longer rebuilds an index from an older graph format inside its own call while a budget is active (it answers from the existing index, `stale: true`, and points to `cortex_refresh`; with `CORTEX_TOOL_TIMEOUT_SECONDS=0` the auto-refresh is unchanged).
- `cortex_refresh` reports progress: `progress(stage, done, total)` through `ingest_repository`, the in-flight `progress` entry in `cortex_status`, and `notifications/progress` when the client sends `params._meta.progressToken`.
- Dead code: `cortex_dead_code` takes `path`; QML bindings, externals, imports, parameters and ids are no longer candidates (they were reported, several at high confidence and some twice); methods marked `@Override`/`override`/`virtual`, declared so in the class header (out-of-line C++), or overriding a method of a base class defined in the repository are reported at low confidence. A method of a class with an external base and no marker is deliberately not flagged.
- Query ranking: Qt Linguist `.ts` files (content starting `<?xml`, `<!DOCTYPE TS` or `<TS`) are text, not TypeScript, so they are no longer parsed as code (`GRAPH_FORMAT_VERSION` 2 → 3: existing indexes rebuild once); translation and locale files are demoted (0.25x) unless the task is about translation; empty items are never packed; files linked by a resolved `calls`/`inherits` edge to one of the 8 best matches are lifted to at least 20 (below a path match). Eval gate, `main` vs this branch in the same environment: macro precision 0.676 and recall 0.875 on the 7 OSS fixtures unchanged; the 17-task matrix is unchanged except one task whose skeleton precision rises 0.500 → 0.667 at equal recall.
- Arguments: an unknown argument returns `unknown_argument` (accepted names and a closest match) instead of being silently ignored; aliases (`cortex_path` `source`/`from`/`target`/`to`, `cortex_references`/`cortex_read_symbol` `target`/`name`, `cortex_query` `query`/`prompt`, search tools `pattern`/`text`), `format` read as `response_format`, and every tool tolerates `response_format`. Four existing tests passed `format`, which had been ignored. **This is a behaviour change for clients that send arguments a tool does not define.**
- Symbols: `path:label`, `path::label`, `Class::method` and `Class.method` resolve; one implementation file beats header declarations of the same name; a name matching nothing returns `symbol_not_found` with `did_you_mean` rather than 20 loosely related symbols (a file path as the "symbol" still lists its symbols).
- `cortex_risk` adds `tests_by_changed_file` and `uncovered_changed_files` next to `tests_to_run`/`tests_run_all`.
- New `scripts/perf/audit_dead_code_credit.py` samples symbols credited only by resolved call edges so their precision can be checked.

Goldens regenerated, each reviewed: `tests/goldens/mcp/initialize.json` (`serverInfo.version`); `tests/goldens/mcp/shapes/cortex_status.{concise,detailed}.json` (new `total_soft_deadline`); `tests/goldens/mcp/payloads/treesitter/cortex_dead_code.{concise,detailed}.json` and `cortex_dead_code.multilang_repo.{concise,detailed}.json` (only QML imports, bindings, a signal parameter and an `id` removed); `tests/goldens/mcp/tools_list.json` (`cortex_dead_code` `path`); `tests/goldens/mcp/shapes/cortex_risk.{concise,detailed}.json` and `tests/goldens/mcp/payloads/{treesitter,regex}/cortex_risk.{concise,detailed}.json` (two new keys); `tests/goldens/evals/default_files.{regex,treesitter}.json` (call-graph expansion reordered one task's selection).

Not done / measured: the reporter's private repository was not available, so the speedups above are from the synthetic repositories. Dead-code analysis is about 25% faster (7.3s → 5.6s), not 2x as the plan hoped; the remaining cost is per-candidate reference scanning. macOS and Windows were not exercised.

## 0.10.1 — 2026-10-19

- Upgrade `tree-sitter-language-pack` from 1.12.5 to 1.22.1 and make future upgrades routine (Dependabot #27). The bump failed CI not because the newer pack needs the network, but because of three Cortex defects: the version is pinned in `pyproject.toml` and in both `runtime-lock.json` copies (with per-platform digests) and Dependabot only edits the first, so site-packages and the managed runtime ended up on different versions; the parser backends imported whichever copy came first on `sys.path` with no version check, so a 1.22.1 module read a 1.12.5 parser cache and every tree-sitter parse silently fell back to regex; and `runtime.py` only knew the 1.12.x cache layout (1.2x keeps parsers under `<cache>/tree-sitter-language-pack/v<version>/libs`). Changes: `runtime._prefetch_and_verify` verifies the locked parser archive and strips setup-only download state in either layout; a new `runtime.language_pack()` (used by the tree-sitter and QML backends) configures the managed runtime before importing and raises `LanguagePackVersionSkew` when the imported pack is not the locked version, and `runtime status` reports `degraded_reason: language-pack-version-skew`; new `scripts/update_runtime_lock.py` regenerates both lock copies and the `pyproject.toml` pin by downloading and hashing every wheel and parser archive (it reproduces the 1.12.5 lock exactly, apart from normalizing one hand-written wheel entry); and `tests/test_runtime_language_pack.py` checks the pins agree and covers both cache layouts. Runtime version 0.8.0 → 0.9.0, so existing runtimes stay in place for rollback and `cortex runtime setup` installs a fresh one. `GRAPH_FORMAT_VERSION` 1 → 2, so existing indexes are rebuilt in full once on their next refresh instead of mixing grammar versions. Verified on Linux x86_64 (Python 3.13): full suite 1739 passed, 44 skipped (the 1732 baseline plus 7 new tests); the only golden regenerated is `tests/goldens/mcp/initialize.json` (`serverInfo.version` 0.10.0 → 0.10.1, the release bump), and `tests/test_golden_mcp_shapes.py` pins the new version; forced-regex suite 260 passed, 335 skipped; `run_evals.py` rows identical to `main` run in the same environment apart from latency; build and `twine check` passed. 1.22.0 refreshed 25 upstream grammars including Swift; Cortex's Swift goldens and evals are unchanged. The macOS and Windows runtimes are covered by `runtime-release.yml`, not by CI.

## 0.10.0 — 2026-10-17

- Task 1: multi-process database safety: WAL, busy timeout and a cross-process ingest lock (`fa46c5c`).
  - Make one Cortex database safe to share between processes: connections use WAL journaling and wait up to 30 seconds for a competing writer (`busy_timeout`), and every ingest holds an exclusive cross-process `ingest.lock` next to the database (re-entrant within a thread, so an auto-refresh that already holds it cannot deadlock). A stale MCP call re-checks freshness after taking the lock and does not ingest again when another process just refreshed; only the call that ingested reports `auto_refreshed`. If the lock stays busy the call answers from the current index as stale instead of failing. Schema migrations no longer mistake a locked database for an already-applied migration. Baseline tests updated: `tests/test_store_connection_baseline.py` (journal mode `delete` → `wal`, busy timeout 5000 → 30000 ms, data dir now holds `ingest.lock` and transient `-wal`/`-shm`) and `tests/test_fingerprint_baseline.py` (stale auto-refresh computes the fingerprint once more, for the post-lock re-check). No golden changed.
- Task 2: fingerprint TTL memo in the MCP process (`58e39b2`).

- Task 4: rename-aware git history for co-change, churn and touches (`b31f799`).
  - Make git history rename-aware. Commits are now read with rename detection, and each commit records its renames (stored in a new `commits.renames_json` column added by an automatic migration). - Add a read-through result cache for `cortex_query`/`cortex_impact`/`cortex_overview` keyed on repo fingerprint (P1-3): a new `query_cache` table (`CortexStore.get_query_cache`/`set_query_cache`/`prune_query_cache`) stores each tool's full response under `cache_key = sha256(fingerprint + tool + canonical_json(args))` (`mcp/tools._cache_key`), computed from the fingerprint `_ensure_fresh` settles on *after* any auto-refresh so a stale-then-refreshed call never caches under an already-wrong fingerprint. A repeated identical call is a single SQLite `SELECT` and skips PageRank/packing (or report generation, or impact ranking) entirely; any file change invalidates automatically, since it changes the fingerprint the key is built from. Cache reads/writes are wrapped in `try/except` so a broken cache degrades to recompute, never to a broken response; error responses are never cached. `CORTEX_QUERY_CACHE=0` disables both reads and writes. `cortex gc` now also prunes each repo's cache (rows older than 30 days, then oldest-first beyond 200 rows/repo) unconditionally, alongside its existing `--prune`-gated orphaned-dir cleanup. ## 0.7.2 — 2026-07-08

- Fix `cortex_search_symbols` (P0) burying the queried symbol under alphabetical, unrelated results. `CortexStore.search_nodes` matched query tokens against each node's `source_ref` (file path) with the same weight as the symbol name, so a query like `CortexStore` matched the *path* of every symbol under `src/cortex/` and ranked `__init__`, `_bfs_proximity`, … equal to the real class (then sorted alphabetically). With no `ORDER BY`, the genuine node could also be dropped by the candidate `LIMIT` before ranking ran. Now the SQL fetches label matches first (`ORDER BY` a label/signature/path priority) so a name match is never truncated away, and the Python ranker buckets strictly name → signature → path, so path-only hits always rank last. (Not related to `enrichment_enabled`, which does not gate symbol matching.)
- Fix `cortex_read_symbol` (P1) returning a single declaration line for C/C++/QML/JS/… symbols. The regex structural backend hard-coded `span_end = span_start`; it now brace-matches the body (skipping strings and comments) to the closing brace, and anchors the line number and signature on the symbol *name* so leading `^\s*` / greedy return-type matches no longer skew the span onto a blank or preceding line. Also fixes `_signature` overshooting toward EOF for a symbol on the final line with no trailing newline.
- Fix `cortex_impact` (P2) listing commit SHAs as impacted paths ranked `1.0`. Commit nodes default to `granularity="file"` and link to files via COCHANGE `touches` edges, so `rank_file_impact` counted them as file neighbors; it now excludes commit nodes with the same guard the community/rank layers use.
- Improve `cortex_query` relevance (P2) when the task names a language or extension: same-language files are boosted and other code languages demoted (multiplicatively, so unrelated files are never seeded by language alone), so e.g. a QML task no longer resolves to the same-named C++ file.
